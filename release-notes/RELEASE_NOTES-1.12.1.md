# rustmd 1.12.1

这一版修正 **PNG / 矢量 PDF 导出里 Markdown 表格的排版**：以前导出会把所有列设成
一样宽，只要表格里有一列长文字，那一列就会被压成每行几个字、行高翻倍，和软件内
预览完全不像。现在导出按与预览相同的规则分配列宽。

## 修复

- **列宽跟预览一致**：导出不再强制等宽列，改用自动列宽。16 行 × 8 列的名单表格里，
  「入选依据」列在预览和导出里都拿到约 410 px（此前导出只有 107 px），行高从
  434 px 回到 89 px。
- **超宽表格不裁列**：表格的最小宽度超过阅读栏（长不可断词、列数很多）时，预览是
  横向滚动，导出改为按表格实测宽度加宽整张图，右侧列不再被切掉。
- **导出高度与清晰度**：同一篇名单笔记的导出从 11292 px 高降到 6040 px，PNG 从
  `2518×30000`（被画布上限压到 2.66×）变成 `2844×18120`（满 3×），文字更清楚。
- **PDF 一并修正**：矢量 PDF 与栅格回退共用同一个导出舞台，表格排版同样按预览列宽。
- CSV / TXT / JSON 数据表使用自己的固定列宽方案（按内容测量），不受影响。

## 验证

- `npm run check`：ESLint、73 个前端单测、仓库/版本/许可/打包检查、`cargo fmt`、
  clippy `-D warnings`、99 个 Rust 测试（Windows）、Vite build 全部通过。
- `npm run selftest`：真实 WebView E2E 覆盖 10 篇示例笔记的 PNG/PDF/HTML 导出与数据视图，
  报告经 `--require-html --require-data` 校验。
- 用一篇 16 行 × 8 列、末列为长文本的名单笔记实测：列宽
  `42/89/42/82/63/45/85/410 px`（与预览逐列一致），行高 `434 → 89 px`；
  另用「200 字符不可断 URL」和「30 列」两张压力表验证导出按实测宽度加宽而非裁列。
